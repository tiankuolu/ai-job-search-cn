# 简历提升与制作

方法来源为项目 third_party/asu-skills/skills/great-resume/SKILL.md 和 make-resume/SKILL.md，采用 ASu 默认单栏高密度模板。完整上游文件和 MIT 许可保存在 third_party/asu-skills/。

## 经历提升

读取完整 JD、个人信息、偏好与 `个人资料/项目事实档案/index.json` 列出的全部档案。根据岗位核心职责确定一个有事实支撑的定位，按相关性选择二至三个项目。每个主要项目使用二至四条，遵循 resume-writing.md 的 STAR 要求。

逐项提取原始事实、个人动作、关键机制、完成状态、验证条件与结果，再形成候选表述。每条表述连接具体问题、行动、形成的系统能力和结果依据。项目代码证明实现存在，实际运行记录证明相应场景的结果，用户确认支撑个人贡献和历史经历。各类依据分别使用。

区分表达缺口、证据不足、真实能力缺口和信息未知。表达缺口直接改写；能够查阅的证据自行核查；已经确认的事实直接使用。对外材料只采用已确认且适用于当前岗位的事实。场景、机制和已验证能力足以支撑结果时，完整呈现其价值。

申请包增加内部 Resume Evidence 节：为关键项目表述记录稳定 ID、原始事实、候选表述、来源位置、确认状态、个人贡献与验证条件。来源包括档案具体章节、源码文件及实际运行记录。修改表述时保留原始事实。强表述需要能够展开的决策、难点、验证与结果。该节供审查与面试复用。

## 简历制作

项目事实使用档案中的稳定编号与来源，个人身份、教育与联系方式使用个人信息，意向和到岗安排使用已确认偏好。新增成果经过源码核查和真实验证后更新档案。保留岗位现有文件中的用户修改。新简历默认生成 ASu 可编辑 HTML 与可选择文字的 PDF，使用蓝色分区标题、浅灰经历条和紧凑项目正文。实际 HTML 模板为 jobsearch_agents/delivery/templates/resume.html.j2，上游设计与编辑组件来自 third_party/asu-skills/。

教育信息保留固定学校名称和 GPA，技能与项目顺序服从 JD。省略经历性质标签。项目时间没有依据时直接省略。没有真实照片时省略照片区域。正文、链接与联系方式均可编辑，HTML 自包含，资源保存在文件内。

preferences.md 的 YAML 元数据 resume.required_skills 指定必须保留的技能表述，resume.skill_categories 指定需要分别列出的技能类别，resume.fixed_awards 指定竞赛与语言的固定条目及顺序，resume.jd_required_experiences 指定需要 JD 明确提及才能使用的经历与技能。模型输出后逐项检查，未符合偏好时进入修改与审查循环，再测量实际页面占用。

所有用户资料只保存在材料目录或被忽略的 runs/、.artifacts/。模板母版保持通用。已有岗位文件保护当前内容；比较任务生成单独命名的目录或文件。

## 生成与审查

Python 读取本规范，以及 great-resume、make-resume 原始技能、claim-evidence-ledger.md 和 page-balance-qa.md。运行记录保存技能文件路径和 SHA-256。采用本项目指定的单一岗位定位、已确认事实、单页与页面占用要求。网页 writer 联合输出岗位定位、ResumePlan、完整版打招呼语和逐条事实编号；独立 reviewer 核查最终正文的原始事实、个人贡献、数字所属项目、测量条件、STAR 与跨材料一致性。模型阶段读取写作与证据规范，页面制作与文件检查由程序执行。完整申请包入口继续按任务需要产生其他文案。

岗位分析关联 JD、资料、规则、提示词与模型配置的摘要，来源变化时重新分析。固定条目使用已确认资料构造，结构与偏好检查在模型审查之前执行。同一稿件的内容审查与实际版面测量并行；字号在9pt至11pt范围逐项实际测量，复用任务内浏览器。内容修正使用 JSON Patch 定位字段，保留其余正文并核查受影响的事实、条件与打招呼语。纯样式改变复用相同内容摘要的审查；正式导出仍执行全部文件检查。阶段结果只有输入与内容摘要一致才允许复用。

使用真实 Edge/Chrome 打印，等待页面与字体加载成功。记录正文占用比例、最小字号和溢出情况。导出的 PDF 必须恰好为 A4 一页，正文必须占用可用高度的 95% 至 100%，目标为 97% 至 99%，最小字号为 9pt，文字清楚、完整、无重叠，所有预期链接存在。占用不足时依据相关项目事实补充内容，重新进行内容审查与实际排版检查；超出页面时精简重复措辞。只有内容和版面均通过检查，才允许交付材料与执行投递。使用 PDF 文字检查和渲染图完成验收。

默认交付可编辑 HTML、PDF 和预览图。只有用户要求 LaTeX 时追加对应源文件。模型输出文本、生成 HTML、导出 PDF 与外部发送分别记录实际状态。
