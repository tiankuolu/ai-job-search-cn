# 岗位分析

按 runtime.md 解析材料目录，读取完整岗位原文、`个人资料/` 的三个文件和相关项目证据。
已有公司岗位目录中的 `岗位JD.md` 以目录名称作为岗位标识，inbox 文件以文件名作为标识。
输出写入 `岗位记录/evaluated/<岗位标识>.md`。

提取公司、职责、必要与优先条件、地点、薪资、届别、到岗要求、来源和招聘时间。
未知信息保持未知，招聘状态与历史保存日期分别判断。已核实违反硬性条件的岗位按用户要求处理。
逐项区分已有证据、可迁移经验、需要补强的能力和需要本人确认的条件。
采用技术 25%、经验 25%、领域 15%、沟通 10%、薪酬与地点 10%、成长 15% 的评分辅助排序，每项注明证据。
分数和优先条件缺失不能自动阻断申请，机会判断遵循工作区根目录 AGENTS.md。

评估保留 `Job Facts`、`Scorecard`、`Requirements Coverage`、`Strengths`、`Gaps`、`Red Flags`、`China-Market Checks`、`Recommended Next Action`、`Assumptions / Missing Info` 等章节，与 Python 提示词中的结构共同维护。
风险判断来自具体事实；普通信息缺失不能推断为负面事实。
项目补强说明具体动作、验证方法和对应岗位要求，完成真实验证后才能更新成果。
